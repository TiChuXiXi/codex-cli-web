# Router 并行交互与停机恢复

2026-11-18，Windows Chrome 通过本机回环地址访问 WSL2 Ubuntu 24.04 上的测试工作台。专用 Router 为 0.169.1，两个临时项目共用原版 Worker App Server 0.170.0，使用真实账号和独立 daemon。Router 通过自然语言收到两次派发。所有用户审批和答题均在 Router 页面完成。

| 临时项目 | Worker 线程末八位 | 用户操作 | 验收证据 |
| --- | --- | --- | --- |
| 临时审批验收 | `285980a7` | 对 `touch -- approved.txt` 点击一次允许 | 原生命令请求来自该回合创建的直接子代理。项目内出现 0 字节的 `approved.txt`，原 Worker 回复“审批验收已写入”。 |
| 临时选项验收 | `208d6bee` | 在松绿和靛蓝之间选择“靛蓝”并提交 | 原线程的 `request_user_input` 收到选项，执行等待步骤，在最终答复中给出“配色验收结果　靛蓝”。 |

两项请求同时出现后先关闭浏览器，重新登录时两张卡都可操作。通过文件审批后立即再次关闭浏览器。重新打开 Router 时，文件任务的原文已经出现，配色表单仍能作答。这些浏览器步骤中，打开或获取 Worker 会话详情的 RPC 数为 0。

提交颜色后，在 20:45:58（北京时间）停止测试 Web 服务。此时配色任务为 `running`，Worker daemon 仍在运行。原生历史在 20:46:25 记录最终答复和回合结束，此时 Web 服务仍处于停止状态，Router 数据库仍记为运行中。重启 Web 后，Router 在原任务下补回最终答复。两个任务均只有一条 Worker 原文，两条自动回执均为 `delivered`。

另以回归用例覆盖错误任务与请求实例的组合、复用原生请求编号后的旧卡、重复提交、结构化消息问题对运行中原回合的插话，以及回合结束后向原线程排队续接。进程重启实测范围为 Web 服务，Worker daemon 在整个过程中持续运行。
