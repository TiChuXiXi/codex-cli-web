# RIP 身份与表达验收

2026-11-20，基于 RCC 分支提交 `2d0ec62` 的工作区实现。页面证据由 Playwright 在实际构建的 Web 工作台中采集。RIP 浏览器用例启动独立服务和临时 SQLite，经认证的设置 RPC 读取并保存配置；Router 原生模型端使用离线夹具。

## 配置效果对照

下表取自同一份共享渲染规则。任务示例的目标均为「发布检查」，状态均为已排队，交付反馈均为标准。每个示例后面还有同一句「等待交付给执行助手。」。

| 预设 | 三个初始档位 | 实际首句 |
|---|---|---|
| 专业干练 | 温和、沉稳、自然叙述 | 「发布检查」的任务已排队。 |
| 自然亲切 | 亲切、轻松、自然叙述 | 好的，「发布检查」的任务已排队了。 |
| 轻松灵动 | 温和、灵动、结论先行 | 已排队，目标是「发布检查」。 |

- 从轻松灵动切换为「分步说明」后，页面显示「基于 轻松灵动 · 已自定义」。标准交付反馈按步骤展示目标状态和交付说明，信息量由篇幅和交付策略决定。「恢复当前预设」重新载入对应的三个档位。
- 「任务已交付」在标准反馈下显示目标会话接收和执行尚未确认；选择「技术细节 · 优先展示」会加入已有的原生确认依据。Steer 所属回合中断时保留执行情况未确认的提示。
- 「Worker 完成」先呈现已有结果；选择「结论加验证」同时展示已有核验信息。仅有终态时报告回合结束及结果说明的缺口。审批、权限、失败、中断和状态未知使用严谨措辞。
- 微信「摘要优先」对超长正文截取开头的摘要并提示工作台查看路径。「分段完整」每片正文至多 1200 个 Unicode 字符，最多三片，后续片至少间隔 2 秒。超过容量的内容在末片提示查看工作台。原生审批保留专用的完整分片、选项和指纹检查。
- 这六个预览场景均使用本地固定事实。普通聊天示例用于展示语言行为；实际模型措辞随上下文变化。预览切换未发起 Router 回合。

旧平面设置读入时保留原 revision，旧文本保留原渠道，旧客户端更新名称后仍保留新策略。对过期 revision、未知版本和未知字段的写入均有拒绝断言。微信回归同时检查已开始发送的长报告收到迟到回执、配置变更及再次 flush 时保留原文分片和发送进度。

本轮验证使用临时目录、模拟模型和 iLink 客户端。未执行真实模型对话、微信真机投递、生产账号操作或版本升级、回滚。上述结果限于 RIP 和所列回归范围。

## 预设保存与运行版本回归

复现了新版页面连接旧 Web 进程时的保存白屏。旧服务忽略结构化设置并返回平面数据，原页面把回包直接作为草稿，读取 `wechatProcessing.typing` 时抛出异常。页面现区分旧设置的兼容读取和新版设置的写入确认，在服务支持结构化配置后才提交，核对回包版本、revision 和人格内容后才更新已保存状态。旧服务或异常回包出现时，页面保留选择，服务更新后可以直接重试。

浏览器用例覆盖旧读回包、旧保存回包、更新后重试，以及通过真实设置 RPC 单独切换「自然亲切」、保存、刷新并核对预设和档位。写入验证使用临时 SQLite。
