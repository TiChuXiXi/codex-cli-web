# RCC P0 验收记录

2026-11-20，Linux aarch64，Node 24.19.0，Worker App Server 0.170.0。临时项目和 SQLite 位于隔离测试目录。测试使用私有 stdio Worker、仅开放回环的网络命名空间及 Responses 夹具。

## 原生链路

从 `RouterService.send` 受理输入开始，夹具在既有 Router 工具入口提交明确的项目和 Thread。服务端校验目标与权限，将原文、派发指纹、指令身份与事件写入同一 SQLite 事务。Dispatcher 领取后调用实际 Worker Hub，向 App Server 提交带 `clientUserMessageId`、`expectedTurnId` 的 `turn/steer`。收到相符的 `turnId` 后落 ACK，从 `thread/turns/list` 按消息 ID 核实历史。Worker 的完成事件通过既有终态事务写回执。

| 情形 | 原生 ACK | 在原 Turn 历史出现的补充数 | 终态回执 | Turn |
|---|---:|---:|---:|---|
| 运行中连续追加三条 | 3 | 3，顺序与原文相符 | 1 | completed |
| 命令审批中追加，测试方随后选择允许临时目录中的 pwd | 1 | 1 | 1 | completed |
| 原生选项输入中追加，再提交选项 One | 1 | 1 | 1 | completed |
| 命令审批中追加，随即中断 | 1 | 0 | 1 | interrupted |

前三项还检查了后续 Responses 请求中的补充标记。中断样本中后续模型输入没有该补充。用户界面分别显示原生接收、历史证据和回合终态。协议不提供逐条业务要求的执行证明。

权限核验会触发原生 `thread/resume`，该操作可重报尚未回答的请求。Hub 按同一连接、请求 ID、方法和完整原始参数保留同一待办实例。协议验收在 Steer 后使用此前取得的审批卡和输入卡作答。

## 延迟与并行

对同一活动 Turn 连续发送三条。测点取服务端受理入口、提交事务后的事件、实际 Hub 调用入口、原生回包，不包含真实 Router 模型推理或微信传输。单位为毫秒，P95 取这三个观测中的最大值。

| 区间 | 第 1 条 | 第 2 条 | 第 3 条 | P50 | P95 |
|---|---:|---:|---:|---:|---:|
| 入站至 SQLite 提交 | 12.28 | 12.98 | 12.80 | 12.80 | 12.98 |
| 提交至调用 Hub | 56.24 | 63.58 | 64.26 | 63.58 | 64.26 |
| Hub 调用至 ACK | 1.34 | 0.98 | 0.85 | 0.98 | 1.34 |
| 入站至 ACK | 69.87 | 77.54 | 77.91 | 77.54 | 77.91 |

在 A 的 Hub 提交调用内注入 30 秒等待，然后才受理 B、C 的输入。从阻塞开始计时，A、B、C 的原生队列 ACK 分别为 30001.27、111.71、109.64 ms。B、C 在 A 释放前均已完成，三个 Thread 的原生历史各匹配自己的指令一次。

## 故障恢复与处置

- 同一 Thread 的下一条普通指令可以持久化，面板显示阻塞它的前序指令编号。审批答复、读取状态和中断原关联 Turn 使用独立入口。
- 未确认的提交会按原生队列 ID 或消息身份对账。自动核对上限为五次，间隔至少 12 秒，同时检查从进入 unknown 起的 120 秒期限。次数及时间随库恢复。达到任一上限，在下一次调度检查生成一次持久提示。微信来源在原绑定仍有效时进入该绑定的发送队列。
- 操作者打开 Worker 核对原文和历史，在任务卡确认关闭。保留 unknown 和关闭时间，释放普通消息顺序屏障；关闭操作的原生发送次数为零。
- 回归覆盖 ACK 丢失后有历史证据和无历史证据两条路径、重启、微信重复入站、一次性超时提醒、旧版和未验证的审批类型延迟、Turn 结束后以同一 ID 续接。原生队列实验另验证忙时抢启动被拒绝、自动消费、队列条目跨私有进程重启和按原 ID 启动。

## 复现

```sh
npm test
npm run typecheck
npm run build
NO_PROXY=localhost,127.0.0.1 no_proxy=localhost,127.0.0.1 npx playwright test test/e2e/router.spec.ts
CODEX_WEB_ROUTER_A1=1 CODEX_WEB_CODEX_PATH="$(command -v codex)" node scripts/test-router-protocol.mjs --rcc-p0
```

最后一个命令输出逐场景证据、三条原始延迟、分位数、30 秒并行结果及 `rccP0Passed`。Linux 需要允许 unshare 并提供 ip。独立的完整 A1 隔离门槛仍使用原命令及其宿主、编译策略参数。

本次覆盖确定目标以后的真实 Worker 链路，Router 选目标和模型响应由夹具控制。真实账号模型、目标共享 daemon 多客户端竞争、0.169.1 的阻塞 Steer 及微信真机收件仍待单独验收。P1 的跨模式、跨焦点语义与 P2 的误派纠正另行验收。
