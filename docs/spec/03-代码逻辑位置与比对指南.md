## 2. 阅读顺序与核心调用链

主 UI：
- src/client/index.tsx.apply：DSH 注入及样式/翻译/RPC 装配。独立项目替换这一层。
- src/client/page/ConsolePage.tsx.ConsolePage：主工作台、项目会话加载、事件分派、选择恢复、请求竞态和发送入口。
- src/client/page/ThreadView.tsx.ThreadView：消息与工具组、滚动、计时、设置、问答、输入区集成。
- src/client/page/Composer.tsx.Composer：输入、命令、附件、技能、文件候选和菜单。
- src/client/sidebar/SidebarWorkspace.tsx：实际右侧工作区装配。RightPanel.tsx 仍有兼容组件/导出，不是当前整体右栏的挂载入口。

后端：
- index.js.apply 创建 EventBus、CodexHub、FollowupQueue、WorkspaceService、TerminalService、Git、Versions，再挂 createRoutes。
- lib/routes.js 把 HTTP 业务端点分发至服务；其 connection 仅在此处提供信任校验，不是 Codex 协议实现。
- lib/hub.js 封装 Codex 业务；lib/jsonrpc.js 负责请求、通知、反向请求、超时和错误；lib/transport/ 负责通信。
- lib/events.js 是事件序列与增量聚合；src/client/events.ts 是浏览器 SSE；src/client/utils.ts.applyDetailEvent 是详情状态合并。

发送链：
    Composer.submit → ConsolePage.send → createApi → HTTP turns/submit
    → FollowupQueue.enqueue/#kick → CodexHub.startTurn
    → JsonRpcClient.request → transport → Codex app-server
    → notification → Hub → EventBus → SSE → ConsolePage → applyDetailEvent → ThreadView

审批链：
    Codex server request → JsonRpcClient / Hub pending
    → approval/requested → ApprovalCard / QuestionForm
    → approvals/respond → CodexHub.respondApproval → 原 RPC 请求响应
    → approval/resolved → UI 更新

文件链接链：
    Markdown.LocalFileLink → 文档打开事件或 FileDownloadButton
    → ConsolePage / SidebarWorkspace → DocumentPane
    → workspace RPC / download → WorkspaceService

Git 链：
    GitPane → api('git/<operation>') → createRoutes.handleRpc
    → createGitService.call → 读写开关 / cwd / 队列 / 参数校验
    → runGit → 结果分类与脱敏 → UI 刷新

## 3. 宿主耦合替换表

| 原位置 | 原依赖 | 新项目处理 | 比对重点 |
|---|---|---|---|
| index.js | ctx.get('connection') / webServer.register | 独立认证与 HTTP 路由 | prefix 与请求处理、认证顺序 |
| index.js / runtime.js | ctx.effect | bootstrap + await close | 创建顺序、关闭顺序、资源计数 |
| src/client/index.tsx | slots / layout | React createRoot 直接挂载 | 业务组件 props、外壳专属入口 |
| src/client/index.tsx | connection.rpc.call | fetch Call 适配器 | 请求信封、result 解包、错误语义 |
| src/client/index.tsx | locale.register | 现有词典及 I18nContext | 默认 t、变量替换、语言字典 |
| scripts/build-client.mjs | ModuleLoader / external React | 独立 ESM/CSS 产物 | React 单实例、字体/CSS、构建常量 |
| src/client/events.ts / uploads.ts / 下载组件 | 页面相对/根路径混合 | 集中 URL helper | 同源、前缀、Cookie、取消、下载 |
| lib/runtime.js | 读取旧入口计算 buildId | 新工程构建信息 | 不残留旧仓库绝对路径 |
| package.json / cordis.patch.yml | dsh 元数据 / Cordis peer | 新独立包清单 | 无 DSH/Cordis运行依赖 |

## 6. 参数和状态专项比对

### 6.1 从边界追踪，不只比较函数名

每条功能记录：
1. 用户操作入口：按钮、键盘、菜单、拖拽、事件。
2. 前端校验：当前会话、项目、busy、disabled、上传和回合状态。
3. payload：字段、默认值、缺失/null、结构化附件/技能/权限。
4. 后端入口：类型检查、认证、真实路径、写开关、取消。
5. Codex/Git/FS/PTY 行为与成功确认时点。
6. 事件：threadId、turnId、itemId、requestId、seq、队列 revision/instanceId。
7. UI 成功与失败：错误类型、草稿保留、选中项、计数和重拉。
8. 生命周期：会话/项目切换、组件卸载、服务退出。

### 6.2 必查竞态

- 切会话/项目后旧列表、详情、模型/设置、文件搜索、图像读取迟到。
- 分页历史和实时事件同时写入，delta、upsert、patch 的顺序与去重。
- turn/completed 早于 turns/start 返回；旧 completed 不能清空新 active。
- 队列编辑时前回合结束、恢复时真实回合仍在运行、多标签页 revision 乱序。
- 审批已由其他页面处理、连接断开请求失效、提交中重复点击。
- 上传取消与服务落盘完成同时发生；源目录 symlink 变化。
- 临时标题生成与手动重命名同时发生。
- Git 写操作串行、stash 引用变化、push 上游不等名。
- 浮动/切换标签引起终端重复挂载，关闭时仍有 read 挂起。

### 6.3 必查视觉逻辑

- CSS 覆盖顺序；根作用域与 root theme token。
- message-content 的 gap 与末尾 Markdown margin。
- 同一工具组折叠/展开状态的分组、计数和可见间距。
- 输入框高度、附件尺寸、上传进度卡片、提示层位置。
- 窄屏抽屉遮罩与滚动、菜单定位、键盘焦点与 IME。
- 右侧 canSplit=false、文档模式、停靠/浮动和全屏。
- 文字选中、消息背景和代码高亮对比度。

## 9. 新项目验收时建议保留的资料

- docs/REFERENCE_BASELINE.md：来源、完整提交、获取方式、LICENSE和NOTICE。
- docs/FEATURE_MATRIX.md：本表的目标映射，逐项真实填写。
- docs/DEVIATIONS.md：独立外壳允许差异，以及修复参考缺陷的证据。
- test/fixtures/：脱敏协议数据、长消息、审批、问题、事件序列和 Git 夹具生成器。
- docs/acceptance/<目标提交>/：环境、自动报告、截图、真实冒烟记录和未通过项。
- 先填源逻辑再实现，再填目标映射和证据；不能完工时只补一张“全部通过”列表。

所有代码和资料的带入遵守原 MIT 与第三方许可证；保留原作者与来源。真实用户上传、认证状态、私密问答、账号和本地研究目录不作为夹具。
