## 1. 必须遵守的任务定义

新建一个独立于 DeepSeek Harness（DSH）和 Cordis 的 Codex CLI Web UI 项目。

**新项目的软件功能、UI 布局、样式、组件表现、交互流程、状态变化、消息呈现和异常处理，必须明确参考并复刻 https://github.com/TiChuXiXi/dsh-codex-cli.git 的现有功能与 UI 源码逻辑。**

本任务不是另行设计一个相似的聊天应用。不得用通用聊天模板代替当前工作台，不得以“独立应用”为由删除文件、Git、终端、队列、技能、审批、提问、版本管理等已有功能，不得擅自重新设计导航、输入区或消息样式。

现有 dsh-codex-cli 仓库继续作为 DSH 插件维护，入口体系、源码、构建、依赖和发布不因新项目而调整。新项目不要求原仓库抽公共库、不向原仓库增加独立入口、不改动原插件 client.js。

“重写新项目”指独立工程、运行环境和维护责任。允许依法复制迁移参考仓库中成熟的组件、样式和业务模块，在新项目内适配维护；不要求为了形式上的重写重新制造已解决的协议和竞态问题。

## 3. 交付与独立性

建议新项目工作名 codex-web-ui；正式 npm 包名、端口和商标文案在发布前确认，不在方案中假定已注册。

交付目标：
1. 独立 Git 仓库及 npm package-lock.json。
2. 独立 Node 后端与 React 前端。
3. 三十八项功能编号对应的代码和验收证据。
4. 构建后的静态资源和 npm 启动入口。
5. 开发、配置、部署、Codex 登录、升级与故障排查说明。
6. 来源、许可证和第三方代码说明。

运行时不安装 DSH/Cordis，不导入原仓库，不依赖其 profile、槽位、模块加载器、认证 Cookie、进程或开发服务器。原插件可单独继续运行；两者数据共享及并发连接边界必须实测，不能承诺同时操控同一回合天然无冲突。

首个正式版本保持已核对 Linux 环境的功能等价。Windows/macOS 需独立验证 PTY、Shell、路径和 daemon 后再声明支持。参考 README 中 Node 24.19.0、Codex 0.167.0 是已验证基线记录，不是本方案宣称的最低兼容版本。

## 4. 总体架构

    浏览器
      独立 React 入口
        ConsolePage 等价工作台
        消息 / 输入区 / 审批 / 项目树 / 右侧工作区
      HTTP RPC + SSE + 二进制上传 + 文件下载
                │ 同源认证
    独立 Node 服务
      CLI / 配置 / 日志 / 静态文件 / 会话认证 / 生命周期
      现有线格式的 /codex-cli/* API
      Hub / EventBus / FollowupQueue / Workspace / Git / Terminal / Versions
                │
      JsonRpcClient + daemon 或 stdio transport
                │
          本机 Codex app-server

保持 HTTP RPC + SSE。PTY 继续使用现有 read 游标与 long-poll 语义，不因独立化引入新的 WebSocket 业务协议。Node 到 Codex daemon 的 WebSocket 属于现有传输实现，与浏览器通道区别开。

以现有业务 API 为边界，不做任意 Codex JSON-RPC 的开放代理。浏览器不直接访问 stdio、Unix socket、Codex 凭据或原始配置文件。

## 5. 技术与工程决策

- Node 后端：ESM JavaScript，沿用成熟 lib/ 的可迁移实现；边界使用 JSDoc/类型约束，暂不以整库转 TypeScript 扩大范围。
- 前端：React + TypeScript/TSX；迁移现有组件与样式，替换装载外壳。不在首版新增路由框架或大型全局状态库。
- 构建：保留 esbuild 经验，新增独立 ESM 前端构建，生成 index.html、JS、CSS 和静态资源；不产生 DSH 模块注册包装。
- React/react-dom：成为新项目显式依赖，由独立前端构建提供，保证单实例。实施时核对源运行环境与依赖兼容性并锁定实际版本；本方案不凭空指定新版本。
- 后端 HTTP：使用 node:http 和显式路由组合即可；静态服务、MIME、缓存、路径边界和认证需完整实现。
- npm 分发：携带预构建前端；终端用户安装后不需要自己编译 UI。
- 继续使用现有图标、Markdown、高亮、Mermaid、xterm、PTY 和 dockkit 方案；依赖锁定后再验证，不为换框架替换视觉与行为。
- 新项目内部清晰分层即可，不要求一开始拆成多个 npm 包或 monorepo。
- 单页先以根路径部署；所有 RPC/SSE/上传下载地址集中由同一 URL helper 生成。子路径部署只有完成专项验收后声明支持。

## 6. UI 复刻契约

### 6.1 主界面

复刻当前 ConsolePage：
- 顶部：左侧栏切换、会话标题及操作、主题切换、右侧工作区开关。
- 左侧：Codex 标识、Codex/SSE 状态、环境/会话/配额信息、新建会话、版本与连接、刷新、项目搜索、新建项目、项目树、会话列表与行菜单、底部健康状态和配额详情。
- 中间：消息列表、工具组、审批/问答、历史回合分页、输入区、模型/强度/权限/计划状态、上下文用量、待发送队列、附件卡片。
- 右侧：当前 SidebarWorkspace，多标签文件/Git/终端/文档、工具选择页、浮动、全屏、尺寸调整、标签菜单及状态记忆。
- 底部：SSE 连接状态、项目分支、会话计数、版本与连接入口。
- 不复刻外层 DSH 页面、宿主侧栏和“返回 DeepSeek Harness”按钮；不增加一个伪 DSH 首页承接退出。

### 6.2 视觉与交互

保留现有组件层次、布局比例、颜色 token、字号、行高、图标、边框、圆角、阴影、动画和响应式断点。样式顺序特别保持基础 styles 与 workbench 覆盖的最终效果。

初期允许保留 .dsh-codex-root、--dsw-* 和 dsh-* 存储键等内部名称，只要新项目不依赖外部提供它们；批量改名不属于实现独立性的前提。若改名，要求自动映射及视觉回归证据。

保留消息末尾 Markdown margin 清零和容器 gap 的组合；测量可见文本/卡片边界，不能只比 DOM 外框。浅色、深色、工具展开、长文、窄屏、文本选择状态都需要金样。

当前右栏 canSplit=false，保留浮动窗口等可达功能，不把残留 split 文案当成开启分栏的要求。通用 browser 标签已退役，不新增浏览器工具；HTML 文档 iframe 预览仍须保留。

### 6.3 必须逐处保持的细节

顶部会话菜单和行菜单的回调不必天然一致，分别按原处复刻。斜杠命令以 COMMANDS/runCommand 的实际动作复刻，不根据命令名称推测语义。后端 threads/unarchive、threads/goal 等接口存在不等于要增加目前没有的 UI。

保留中英文词典与当前默认展示，独立入口提供 t；不以“加入语言切换设置页”扩展首版需求。当前 ConsolePage 中 provider 固定为 openai，不据历史代码或测试推断应新增多提供商控制台；Codex 当前配置所支持的模型能力仍按基线读取。

## 7. 主流程与状态规则

### 7.1 启动与恢复

1. CLI 读取参数、环境和应用配置，检查监听地址及配置格式。
2. 初始化应用认证、HTTP/静态服务、runtime 和各业务模块。
3. Hub 在后台建立 Codex 连接；Codex 不可用时页面仍可打开并显示错误与诊断。
4. 浏览器完成 Web 认证，再加载 status、项目、模型、配额和 pending。
5. 打开 SSE，恢复最后项目与会话；拉取详情、设置、队列并建立会话订阅。
6. 每个请求携带或绑定当前会话/项目身份；响应过期则丢弃，不覆盖当前 UI。
7. 页面关闭释放自身引用；后端队列的保留订阅独立存在。

### 7.2 发送与队列

用户输入文本/附件/技能 → 校验上传状态 → 组装模型、强度、权限与 collaborationMode → turns/submit → 后端按会话串行操作队列。

空闲可开始回合；运行中消息进入 FIFO。sending 只表示已在调用，直到得到回合确认才完成移交。回合完成事件可能早于 start 返回，必须沿用防竞态逻辑。

编辑队首期间阻塞自动发送；保存回到 queued；取消恢复原项；引导走 turns/steer 并在成功后移除项。停止回合、失败或 Codex 断线暂停队列；用户点击继续后同步真实活动状态再恢复。不得在不知道上一次提交是否成功时盲目自动重试。

### 7.3 审批与问答

Codex 反向请求 → Hub 记录 pending → SSE 通知 → 对应会话卡片 → 用户提交 → approvals/respond → 原请求响应 → resolved 事件。

命令、文件变更、权限、elicitation 和 userInput 各自响应格式不同。同步问答保留原 requestId；异步问答属于消息交互，运行中引导，空闲提交后续回合。选择默认首项不是自动提交。

### 7.4 SSE 与重连

浏览器 EventSource → Last-Event-ID → EventBus.since → 重放或 resync → 当前视图重新拉取快照。沿用原 seq、增量合并、item upsert/patch 和快照去重。

SSE open 不代表 Codex ready；两类状态独立。后端重启造成 epoch 变化或 seq 回退时需要重新同步，不能默默继续使用旧队列 revision。首先复刻基线；发现缺陷时在新项目差异记录中给出复现和修复，不回写原插件。

### 7.5 工作区与终端

当前 cwd → workspace/open → workspaceId → 文件读取/搜索/预览/上传下载/观察。切项目取消旧请求和观察，释放旧项目终端。

终端的创建与关闭绑定标签/项目生命周期，切标签或收起不销毁；页面刷新重新建立 Shell。浮动和停靠不应触发重复 PTY 创建。文件与 Codex 回合的权限语义分别处理。

## 8. 状态归属与持久化

| 状态 | 权威归属 | 生命周期 |
|---|---|---|
| Codex 会话、历史、回合、配置 | Codex | 由 Codex 管理，新应用不复制数据库 |
| pending 审批 | Hub/当前 RPC 连接 | 断线按基线处理，不伪造跨进程可恢复 |
| 待发送队列 | Node 内存，按 threadId | 浏览器离开保留；Node 重启清空 |
| SSE 环形缓冲 | Node 内存 | 不持久化，缺口走 resync |
| 文件观察、Git 作业、PTY | Node 服务 | 显式创建释放；PTY有失联回收 |
| 主题、项目顺序、侧栏布局、未读信息等 | 当前源码所用浏览器存储 | 保留原有 localStorage/sessionStorage 区别 |
| 草稿、完成附件和技能引用 | 按会话浏览器草稿 | 原基线 sessionStorage 语义；不承诺跨设备 |
| 上传中临时文件 | Node 临时目标 | 取消/失败清理，成功原子发布 |
| Web 登录状态 | 新应用认证模块 | 与 Codex 账号、DSH 登录完全独立 |

逐键登记实际存储位置、版本和清理策略。独立站点 origin 不同，默认不会自动迁移旧插件浏览器偏好；仍可通过同一 CODEX_HOME 读取已有 Codex 会话。首版不新增数据库和队列持久化，以免偏离基线。

## 9. 外部接口

业务路径首版继续使用 /codex-cli，减少迁移变量。新前端适配器替换 ctx.connection.rpc.call，保持 createApi 的值/异常语义。

POST /codex-cli/<endpoint>：
- 请求：{ type: "client-request", rpcId: "<唯一字符串>", method: "<endpoint>", payload: {} }
- 响应：{ type: "server-response", rpcId: "<相同值>", result: { ok: true, value: ... } }
- 业务失败：result 为 { ok: false, error: { code, message, details } }。
- 不把 result.ok=false 误当作成功；保留请求端点与 method 一致检查及取消信号传递。
- HTTP 401/403、非法内容类型、体积超限与业务错误分别处理。

其他通道：
- GET /codex-cli/events：认证 SSE。
- POST /codex-cli/upload/file：二进制附件流，query 中 cwd/name/size；流量校验和临时文件处理按基线。
- GET /codex-cli/workspace/download：认证单文件下载，Unicode 文件名和二进制不损坏。
- 新增 /healthz：只返回进程存活，不泄露路径/账号，不代表 Codex ready。
- 新增 /auth/login、/auth/logout、/auth/session：独立 Web 认证所需的最小接口。

业务端点清单及每项来源见第三份文档。精确字段以锁定提交 lib/routes.js、lib/git.js、types.ts 和前端调用处共同核对；对照表不是从头推测的新 API。

## 10. 独立外壳需要新增的实现

### 10.1 认证与访问

这是替代 DSH 原有信任栅栏的新增基础设施，属于允许差异。

首版面向单一可信操作者：默认 127.0.0.1，支持显式配置局域网监听和允许的 Host/Origin，不做多租户账号/项目授权系统。

启动时生成或读取应用访问凭证；浏览器通过简洁登录页交换为 HttpOnly、SameSite Cookie，会话带有效期，HTTPS 时 Secure；凭证不进入前端 bundle、请求 URL 或日志。登录失败限流；会话失效有明确恢复入口。

所有业务 API、SSE、上传、下载和终端走统一认证及 Host/Origin 校验；写请求检查同源/防 CSRF 规则，不能将 requestRejection 改成始终返回 undefined。明确兼容浏览器无 Origin 的正常只读请求，而不是简单“无 Origin 一律通过”。

Codex 登录沿用宿主已有 codex login/配置，不新增模型账号托管；Web 登录不代表 Codex 已登录。

### 10.2 配置与日志

新项目约定优先级：CLI 参数 > 专用环境变量 > 应用 JSON 配置 > 默认值。CODEX_HOME 解析保持显式 codexHome > 环境 CODEX_HOME > 默认目录。不要改写用户 Codex 配置来实现应用自己的配置。

基础参数：host、port、应用配置路径、认证配置、codexPath、codexHome、transport、git 写开关、日志级别。Codex 原有配置默认值以基线 normalizeConfig 为准。

日志保留连接、作业、启动关闭和结构化错误；不记录密码、Cookie、Token、私密问答和原始凭据。Git 日志继续脱敏。

### 10.3 生命周期

bootstrap 返回可等待的 close()。停止接收新请求，取消上传和长轮询，关闭 SSE，停止队列调度及观察，释放终端/Git 作业，等待 hub.stop，释放总线与计时器，最后关闭 HTTP。

为关闭设置有限等待和最终兜底，不让未关闭 SSE 卡死退出。私有 stdio 子进程由本应用清理；仅断开共享 daemon，不默认对外部 daemon 执行 stop。

runtime 的 buildId/instanceId 改由新工程入口及构建信息产生，不再硬编码读取旧插件路径。

### 10.4 静态构建与路径

新前端使用 createRoot，不实现 DSH 的 slots/layout/module loader 兼容层。样式注入如依赖 __CODEX_BUNDLE_CSS__，应由新构建显式提供或导出 CSS，不能漏掉 xterm/vendor 样式。

同源服务前端和 API，开发环境代理亦遵守同一地址约定。SSE 禁止代理缓冲；静态资源 MIME、SPA fallback、缓存和异常页面明确；fallback 不截获 /codex-cli 或 /auth。

## 11. 默认限制与语义基线

| 项目 | 基线要求 |
|---|---|
| 浏览器会话列表 | 默认每页 5 条 |
| 消息回合分页 | 默认每页 2 个回合 |
| SSE 缓冲 | 默认 5000 条 |
| delta 合并 | 40 ms 窗口 |
| SSE keepalive | 15 秒 |
| 审批超时 | 默认 600000 ms；0 表示不自动超时拒绝 |
| Codex 重连退避 | 基数 500 ms，上限 15000 ms |
| 普通 RPC 请求体 | 默认 2 MiB，特定上传兼容端点单独处理 |
| 对话二进制附件 | 单文件 500 MiB |
| 工作区/Base64兼容上传 | 单文件 25 MiB，不能混同二进制大附件 |
| PTY | 最多 16；每终端输出缓冲阈值 1 MiB；失联超过 5 分钟回收 |
| 左侧宽度 | 默认 280px，260–420px |
| 右侧恢复宽度 | 默认 480px，320–1100px，实际窄屏行为按 CSS |
| 工作区布局 | 当前不开放 split；保留标签、浮动与全屏 |

数值作为锁定提交的复刻基线，不预先做性能调参。涉及存储编码、输出截断和平台字符计量时，最终以代码判断为准。

## 14. 验收策略与完成定义

配套手册中的 38 个编号都要有结果；R-03 为独立外壳新增项，其余以行为等价为主要标准。

验收分为：
1. 代码比对：源路径/符号、目标路径/符号、修改理由、参数/状态/清理差异。
2. 模拟协议验证：无需模型账号，重现消息顺序、超时、重连、审批、快速回合。
3. 临时文件/Git/PTY 集成：隔离夹具，输出及资源回收验证。
4. UI 与视觉：相同数据、viewport、字体、时区和主题；禁用不稳定动画，屏蔽随机时间/ID；不屏蔽布局缺陷。
5. 真实 Codex 冒烟：明确版本、CODEX_HOME、账号/配置，覆盖关键闭环；不能以模拟通过替代。
6. 干净环境安装：无 DSH/Cordis、无原仓库和开发依赖，安装打包产物后运行。

每条记录“通过/失败/阻塞/不适用”，附 commit、截图/日志/测试报告与问题号。未实现或未执行标记清楚，不打勾。仅因无网络、无真实账号或平台不支持导致的阻塞不能记为通过。

允许差异限定为：去除 DSH 宿主入口；新增独立启动/认证/配置；通信外壳和资源构建适配；内部路径调整。其他差异需记录用户体验与原因，不默默简化。安全/竞态缺陷可在新项目修复，但必须保留对照复现与回归证据。

## 15. 安装分发与文档

首版采用 npm CLI 包，提供 bin 启动命令，携带 dist/web 与后端代码。安装/启动帮助明确 Codex CLI、Git、支持平台和 optional PTY 包前提。

预期体验为安装新包后执行 codex-web-ui；包名与 npx 示例在正式发布后填写，不能把占位名称写成已可安装产品。

应用不自动安装完整 DSH，不修改旧插件配置。Codex 首次登录说明沿用 CLI；版本管理动作由用户明确触发。

Docker 和单二进制作为后续分发选项：前者改变文件/终端所在环境，后者须处理 PTY 原生资源与外部 Codex/Git。首版不并行承诺这两种未验证形态。

## 16. 实施风险与控制

- 最大工作量在完整回归和边界一致性，不在画一个聊天页面。以编号和代码映射避免漏项。
- app-server/daemon 能力随 Codex 版本变化。按基线迁移后，记录实际兼容版本和降级，不凭接口名称保证支持。
- 新 Web 认证替代宿主认证，必须覆盖全部传输入口；不能只保护首页。
- dockkit、Mermaid、xterm CSS 和构建全局常量容易漏迁。首屏、工具区和文档场景一起验证。
- 浏览器存储与内存资源生命周期不同。刷新、关页、切项目、关标签、退出服务分别测试。
- 原插件与新应用共享 CODEX_HOME 的并发行为需实测；验收优先用隔离配置与模拟服务。
- 非公开测试夹具、截图、上传文件和真实认证状态不带入发布仓库。
- 本文档不估计承诺工期；S0/S1 后按真实迁移差异和功能矩阵估算。任何“完成”声明必须满足第14节，而非只看构建成功。
