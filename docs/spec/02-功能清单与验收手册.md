## 使用方法

新软件必须参考复刻上述仓库的功能与 UI 源码逻辑。以下清单既是功能范围，也是验收案例；编号在三份文档之间一致。

验收人员先记录环境，执行每项操作，对照“预期”和边界，再到第三份文档核查源码实现。每项可能包含多个子场景，全部通过才可标记本项通过。

本手册覆盖可见功能与必要支撑逻辑。R-03 是替代 DSH 宿主的新增基础设施，不能据此要求源插件已有登录页。后端保留接口不自动转成新 UI 需求。

## 分项操作与预期

以下每项同时比对浅色/深色；涉及布局、菜单、输入区、消息和右栏的项还需窄屏验证。预期来自锁定源码行为；接口或平台能力不可用时记录阻塞及错误呈现，不伪造成功。

### UI-01 · 工作台布局

**操作步骤**

1. 打开首页。
2. 选择会话。
3. 收起及展开左右侧栏。
4. 拖动左侧宽度。
5. 刷新页面。

**预期结果**：复刻品牌区、连接信息、项目树、顶部操作、消息区、输入区、右侧工作区和底部状态栏；左栏默认 280px，范围 260–420px；界面状态按基线保存。移除返回 DSH 的专属入口。

**边界与失败路径**：按可见内容边界比对间距；截图名称和旧设计文档不覆盖当前 CSS。

**代码核查**：[UI-01 对照条目](03-代码逻辑位置与比对指南.md#ui-01)。检查参数、状态变迁、异步过期响应、成功/失败反馈与资源释放，不只比较正常路径。

### C-01 · 输入、发送、草稿与历史

**操作步骤**

1. 输入多行、中文和纯附件消息。
2. Enter 发送、Shift+Enter 换行。
3. 切换会话恢复草稿。
4. 模拟发送失败。
5. 在输入边界用上下键浏览历史。

**预期结果**：空消息禁止发送；组合输入不误发送；发送成功清理输入，失败保留文本附件；草稿按会话隔离；上传未完成时禁止提交；历史导航遵循现有光标边界规则。

**边界与失败路径**：草稿不等于后端待发送队列；不承诺跨浏览器或跨设备草稿同步。

**代码核查**：[C-01 对照条目](03-代码逻辑位置与比对指南.md#c-01)。检查参数、状态变迁、异步过期响应、成功/失败反馈与资源释放，不只比较正常路径。
